# Serenity transport security patch

This is the crates.io Serenity 0.12.5 package, SHA-256 9bde37f42765dfdc34e2a039e0c84afbf79a3101c1941763b0beb816c2f17541, with only its tokio-tungstenite requirement and gateway transport API adapters changed. The manifest selects 0.30 rather than 0.21, allowing the locked patched Rustls 0.23.46 line and removing Rustls 0.22 / WebPKI 0.102. Text/close payload conversions and the WebSocketConfig builder track the new transport API. All TLS verification stays in the maintained upstream Rustls/WebPKI stack; no cryptographic implementation is forked.

The original license and VCS provenance are retained. Remove this patch when a compatible Serenity release uses the fixed transport. Local dependency, transport, security and full bot gates must pass; this patch does not qualify live Discord voice or deployment.

The standalone test Cargo.lock is generated by Cargo and selects Reqwest 0.12.28 and HTTP 1, matching the application's HTTP API line. This avoids the published crate's unconstrained standalone test resolution selecting incompatible HTTP/Reqwest versions. The gateway source includes two loopback tests for JSON events and close-frame reasons; check.sh runs them with the test lock frozen. The added .gitignore excludes only the generated standalone target directory.

The token-format documentation example is replaced with `example.synthetic.signature` so the vendored upstream example cannot be mistaken for a credential by push protection. This changes no runtime code or token validation behavior.
